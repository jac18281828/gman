This is a fairly large program.  For my own personal benefit I still

Watt and their books \em 3D Computer Graphics,\rm and Advanced

would have been untenable.

\section{About GMAN}
The RenderMan standard asks a great deal of a renderer\footnote{Thanks to
Larry Gritz of Pixar for this list.}:

\begin{enumerate}
\item{High-end geometric types, such as trimmed curves, NURBS and
      Catmull-Clark subdivision surfaces.}
\item{Robust spatial and temporal antialiasing, 
      including motion-blurred geometric deformations\footnote{Whoa!
That's a mouthful.}}
\item{Programmable shading of surfaces, lights, and volumes.}
\item{Displacement shading.}
\item{The ability to use large numbers (e.g. hundreds or thousands)
      of large textures without memory consumption growing appreciably.}
\item{Fine control over quantization, filtering and reconstruction of
      images.}
\item{Variable quality in rendering algorithms, providing fine
control over shading time versus shading quality.}
\end{enumerate}

That list is the target, not the inventory.  \gman renders the quadrics
and convex polygons today, shaded by \text{ matte, plastic } and \text{
metal, } lit by ambient, distant and point lights, and does none of the
seven things above.  Choosing RenderMan as a starting point still looks
like a good idea.  The standard says what finished would mean, and I can
walk toward it a piece at a time.

\section{Overview}

GMAN supports three interfaces for its scene description language, C,
C++, and RIB.  The C interface is provided in the \text { ri.h }
header file.  The C++ interface is provided through the \text{
gmanrenderman.h } header file, in the \text{ GMANRenderMan } base
class.  The C interface is built out of the C++ Interface by providing a
C wrapper that instantiates a single instance of \text{
GMANRenderManImpl, } the RenderMan implementation class.

\subsection{Object Management}
\gman stores all objects defined with a \text{ RiWorldBegin,
RiWorldEnd } pair in an object database called an \text
{ ObjectManager. }  The object manager base class is defined in \text
{ gmanobjectmanager.h. }  One is implemented, the linear world manager;
the BSP and octree managers were designed and never written.  The
\text{ ObjectManager } interface provides a generalized method for
accessing all objects in a World, i.e., all objects to be projected
into the output view by the shader.

\subsection{Shaders}
\gman also provides a generalized interface to shading algorithms.
These shading algorithms, or Shaders for short, are implemented
through an abstract base class, \text { GMANShader, } defined in \text
{ gmanshader.h. }  Any class derived from a \text { GMANShader } object can
be specified as the shader used in a particular GMAN rendering
session.  This allows for extreme flexibility in implementation, and
reuse of \gman code, even where a different rendering algorithm is
desired.  This also provides a mechanism where under the LGPL, shaders
can be created in a client application that do not fall under the
terms of the license, as they need not be added to the \gman library,
they can be specified as part of the client application and integrated
into \gman at runtime.
